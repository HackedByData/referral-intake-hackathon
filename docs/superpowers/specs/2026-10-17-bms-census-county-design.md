# Addendum: county-aware bed management from IHH's census

**Date:** 2026-10-17 · **Status:** Approved in chat · **Extends:** [`2026-10-17-referral-intake-design.md`](2026-10-17-referral-intake-design.md) §8 (Bed management)

## Why
IHH manages beds in a multi-sheet Excel census, one sheet per facility. The BMS must hold the same information, and a
referral may only be matched to a **recuperative-care facility in the patient's county**.

## Source workbook (confirmed synthetic by an organizer; kept OUTSIDE the repo at `../Test Census.xlsx`)
- About 30 sheets, about 22 of them facilities with data. A "Drop Down" sheet holds the payer list (Anthem, Blue Shield,
  DHS, Health Net, LOA, LOS, Kaiser, LA Care, Molina, Blue Cross, Cal Optima). Empty sheets: Sheet1–Sheet7, Alhambra,
  Buena Park STPH, SB1, Buena Park M.
- Header row is the first of rows 1–3 that contains a cell starting with `IF` (`IF#`, `IF #`, `IF/IE#`).
- Bed tables can repeat side by side (SFS, Lincoln Park, Coral, MWC, Broadway, RVS, Royal Pagoda, Laguna Hills,
  Anaheim). A block starts at a header matching Bed/Room/Rm (`Bed`, `Bed#`, `Bed/Rm#`, `Bed/RM #`, `Room`, `Room #`,
  `ROOM#`, `Rm #`, `Room #/Bed #`, `Room#/ Bed#`). Some blocks have a junk first header (`` ` ``, `///`, `/`).
- Header cells may also contain summary counters ("Current Census: 0 People", "Female Beds Avail: 0"). Ignore them.
- Status words appear in the first-name cell. See the mapping below.

## Data model (additive)
- **Facility** (`Site` table): `county: str|None`, `program_type` ∈ `recuperative_care | project_roomkey | shelter |
  other | unknown` (default `unknown`), `address`, `phone`, `notes`, `active: bool = True`.
- **Bed**: status ∈ `available | occupied | needs_cleaning | out_of_service`; `held` stays derived from holds.
- **Stay** (`Assignment` table): `referral_id` becomes nullable; adds `source` (`referral | census | seed`),
  `client_id`, `first_name`, `last_name`, `gender`, `intake_date`, `exit_date`, `payer`, `case_manager`,
  `stay_notes`, and `extra_json` (every other source column, verbatim, keyed by header). This is the per-bed
  **patient info section**. The existing `expected_end_date` is the expected exit.
- The local DB lives in `data/` (gitignored). A schema change means deleting `data/app.db` (prototype; no migrations).

## Status mapping (first-name cell, case-insensitive, trimmed)
| Text | Result |
|---|---|
| `open`, empty with a label | available |
| `needs cleaning` | needs_cleaning |
| `closed`, `do not use`, `unavailable`, `offline`, `no bed`, `xxx`, `@sfs`, `no light`, `no tv`, `sink` | out_of_service (original text → bed notes) |
| `staff`, `staff restroom`, `sm office`, `office`, `nursing station`, `donning room`, `doffing room`, `med room` | not a client bed → skipped, reported |
| IF# present (`IF…`/`IE…`) | occupied + stay |
| any other name text without IF# | occupied + stay (client_id empty) |
Labels containing `ADA` → `wheelchair_accessible=True`. Rows whose label is a summary (`Total…`, `Female Beds…`,
`Male Beds…`, `Total Client`, `0/34`) are skipped.

## Matching (hard filters, in `beds.service.find_matches`)
Facility `active` · `program_type == "recuperative_care"` · `county` equals `needs.county` (case-insensitive, trimmed) ·
bed available and not held by another referral · then the existing sex/wheelchair/oxygen/isolation rules and ranking.
`needs.county is None` → no matches.

## Patient county: the AI extracts, code maps, the coordinator confirms
- `CaseSummary` gains `health_plan`, `health_plan_evidence[]` and `location_clues[]` (cited quotes). The AI never names a county.
- `criteria/plan_county.json` (editable) maps unambiguous single-county Medi-Cal plans to a county. Multi-county
  plans map to `null`. IEHP lists two candidates, which means no suggestion.
- The pipeline sets `summary.suggested_county` (`CountySuggestion`) and `bed_needs.county`. Unknown → no hold; the
  tree's bed node emits review reason `county_needed` (instead of `no_bed`).
- `POST /api/referrals/{id}/county {county, coordinator}` confirms or overrides. It re-runs `decide()` on the stored
  results with new matches, re-holds, saves, and audits. No AI calls.

## Census import and POC seed
- `POST /api/census/import` (xlsx) parses the workbook with `app/beds/census.py` and upserts facilities and beds by
  (facility, label). It replaces `source="census"` stays with the workbook's snapshot and never touches
  `source="referral"` stays (a disagreement is reported as a conflict). Returns `CensusImportReport`.
- **POC seed (user request: "seed everything with placebo data").** `app/beds/seed_poc.json` is committed. It is generated by
  `tools/build_poc_seed.py` from the workbook's **structure only**: facility names, bed labels and statuses. Counties
  and program types are **POC placeholders** (each facility's notes say so). Every occupant is invented
  (`Test Client NNN`, placeholder IDs, a payer from the Drop Down list). No name, ID or date is copied from the workbook.
  Seed loads on an empty DB and replaces the old two-site demo seed.

## API (contract v2, additive)
`GET /api/facilities` · `PATCH /api/facilities/{id}` · `GET /api/beds/{id}` (bed + current stay with `extra` + history) ·
`POST /api/census/import` · `POST /api/referrals/{id}/county`. `BedView` adds `site_id`, `county`, `program_type`,
`stay` (summary). `ReferralView` adds `county` (`CountySuggestion`). `ReviewReason.kind` adds `county_needed`.
`BedStatus` adds `needs_cleaning`.
